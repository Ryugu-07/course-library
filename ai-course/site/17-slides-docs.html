第 17 讲 · 实战：PPT 与文档

一份演示不是把长文切成十几块，而是在有限时间内安排一条可验证的注意力路径。AI 可以帮助整理、变体生成和一致性检查；它既不会天然理解你的论证，也不能替听众保证“看懂了”。

学习层：七分钟报告，听众最后能复述什么？

1. 具体谜题：材料都正确，为什么报告仍然失败？

你有一组实验结果、两段背景和一条限制条件。把它们全部放进页面，内容可能没有一句是假话，报告却仍可能失败：听众不知道你要他们记住什么，主张与证据隔了三页，图没有单位，结论超出数据，最后还因字体替换导致公式错位。

这不是单纯的“美化”问题，而是信息架构、证据和交付环境共同决定的工程问题。

2. 先预测：READY、REVISE 还是 BLOCKED？

实验使用完全虚构的项目“Atlas 教学检索助手”。选择一个故事板预设，先判断最终交付状态：

  • READY：内容支持与交付检查都通过；
  • REVISE：主张仍可支持，但表达、可读性、可访问性或文件交付需要修改；
  • BLOCKED：核心主张缺证据或越界，不能靠排版修好。

然后运行四关：受众与讯息、主张与证据、视觉编码与可读性、来源与可访问性。

3. 最小模型：一页只承担一个认知动作

一个紧凑故事板可用四类页面角色组织：

  1. 问题：让听众知道为什么现在要关心；
  2. 主张：用完整句标题给出这一页希望听众带走的判断；
  3. 证据：图表、对照或实例直接支撑主张，并标明单位、样本和来源；
  4. 行动 / 边界：说明下一步，以及当前证据不支持什么。

“判断句标题”属于 assertion–evidence 设计纪律：它让标题承担主张、主体承担证据。它很有用，但不是所有页面的唯一模板；目录、演示、讨论和过渡页可以承担不同角色。

时间也是硬约束。实验用一个透明预算：开场与收尾各占约 45 秒，内容页按每页约 50 秒估算。它不是演讲学定律，只是提醒你：页数、动画步骤和口头解释都会竞争同一段时间。

4. 动手验证：看清究竟卡在哪一关

调节受众、时长和页数预算，观察同一组材料如何改变故事弧。审计台不会“自动审美打分”，只执行公开规则：标题是否提出可辨认主张、核心主张是否有相邻证据、图是否具备轴/单位/来源、页面密度是否超预算、颜色是否有第二编码、关键视觉是否有替代文本、字体是否嵌入或有可移植后备。

无 JavaScript 时的静态读法：

预设 内容支持 交付就绪 原因
背景式标题 SUPPORTED REVISE 标题没有告诉听众本页判断
主张缺证据 UNSUPPORTED BLOCKED 核心提升幅度没有相邻证据
过载页面 SUPPORTED REVISE 字数与口头预算冲突
图表缺单位 / 来源 UNVERIFIED BLOCKED 数值无法解释或追溯
完整故事板 SUPPORTED READY 四关通过，仍需真人彩排

5. 误区与边界

  • AI 不天然擅长逻辑、也不注定不擅长视觉。能力取决于材料、约束、工具和审校；重要主张仍需作者负责。
  • 讲稿不是页面。页面提供定位与证据，讲者备注承载转场、限定词和口头解释。把完整段落贴上去，会迫使听众在读和听之间抢占注意力。
  • 源文件优先于截图。流程图和示意图应尽量保留 Mermaid、绘图代码或矢量源；截图只适合记录必须展示的界面状态，并要有清晰裁切、分辨率与说明。
  • 颜色不能独自编码意义。同时使用标签、线型、形状或位置；关键视觉提供 alt text，装饰图则不应制造朗读噪声。
  • 本机好看不等于可交付。提交前检查投影比例、最小字号、对比度、视频与链接后备、PDF/PPTX 字体嵌入，以及另一台机器上的实际渲染。

6. 回到方法：内容支持和交付就绪分开判

一个故事板可以内容正确但尚未 READY，例如文字过密或字体未嵌入；也可以视觉整洁却因核心主张无证据而 BLOCKED。把两本账分开，团队才知道该找研究者、编辑、设计者还是演讲者修复。

7. 迁移问题

把同一份研究结果分别讲给本领域同行和跨专业管理者。哪些主张必须保持不变？哪些背景、图例和行动建议应改变？请说明“简化表达”与“削弱证据限定”之间的界线。

1. 先立论证，再选工具

开始制作前先写一句核心主张、三条支撑、听众画像、时间预算和希望听众采取的行动。让 AI 生成多个结构候选是合理的，但最终结构必须由你根据证据关系决定。

可用提示骨架：

报告时长：[分钟]；听众：[已有知识与关心的问题]；
目标：[听完后能解释或决定什么]；材料：[来源与限制]。
先输出：一句核心主张、3 个支撑、每页角色、判断句标题、
证据定位和讲者备注。不要补造数据或来源。

2. 选择可维护的成稿路径

路径 特点 适合场景
大纲协作 + 手工排版 控制力最高，人工成本高 答辩、重要外部报告
文本化 slides 可版本管理、易复现 技术分享、课程
结构化脚本生成 PPTX 适合批量与模板约束 周报、标准化汇报
在线演示产品 快速协作，需检查导出与隐私 低风险初稿

工具会变化，稳定的资产是论证结构、数据源、图表代码、视觉规范和验收清单。

3. 图表与视觉证据

  • 数据图由真实数据或可复现代码生成，标清坐标轴、单位、样本、误差定义和来源。
  • 逻辑图保留可编辑源文件，导出 SVG/PDF 等矢量格式；需要展示真实界面时才使用截图。
  • 插图用于建立场景或帮助记忆时，要与事实证据明确分工，不能让生成图冒充观测数据。
  • 投影环境通常比笔记本屏幕更苛刻；用实际距离预览，避免依赖细线、低对比色和细小图例。

4. 长文档工作流

长文档同样先建立章节树、每节主旨和依赖关系，再逐节起草。每轮生成都带回全文骨架、术语表、已确认事实与待核问题；最后分别运行事实审校、结构审校、语言审校和格式验收。AI 可以辅助发现不一致，但不能替作者确认来源、保密边界或最终责任。

5. 交付清单

  1. 核心主张与证据逐页相邻，限定词没有在标题里消失；
  2. 每张图有单位、来源与可读图例，颜色具有第二编码；
  3. 页面承载视觉骨架，备注承载讲稿；
  4. 用目标设备彩排并记录实际用时；
  5. 检查 PPTX/PDF 字体、视频、链接、动画和离线后备；
  6. 保存数据、绘图代码、图源与最终导出版本。
